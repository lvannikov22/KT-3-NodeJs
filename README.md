# КТ-3. API с базой данных

Небольшой учебный API для блога. Используются Node.js, Express, Prisma 6, Joi и SQLite. SQLite выбрана, чтобы не устанавливать PostgreSQL.

## Запуск

Нужен Node.js 22 или новее. Открыть терминал в папке `kt03`:

```powershell
npm install
Copy-Item .env.example .env
npm run migrate
npm start
```

Если `.env` уже есть, копирование можно пропустить. Сервер: http://localhost:3000. База находится в `prisma/dev.db`. После перезапуска данные остаются.

## Файлы

- `prisma/schema.prisma` — таблицы User, Post, Tag и роль USER/ADMIN.
- `prisma/migrations` — SQL миграция.
- `src/index.js` — запуск Express и подключение маршрутов.
- `src/config/index.js` — настройки из `.env`.
- `src/routes/users.js` — работа с пользователями.
- `src/routes/posts.js` — работа с постами и тегами.
- `src/middleware/validate.js` — проверка данных через Joi.
- `src/middleware/errorHandler.js` — обработка ошибок.

Логика написана прямо в маршрутах, без сервисов и дополнительных слоев.

## Маршруты

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | /api/users | Список пользователей, page и limit |
| GET | /api/users/:id | Пользователь с постами, новые посты сначала |
| POST | /api/users | Добавление пользователя |
| PATCH | /api/users/:id | Изменение пользователя |
| DELETE | /api/users/:id | Удаление пользователя |
| GET | /api/posts | Список постов с фильтрами и пагинацией |
| GET | /api/posts/:id | Пост с автором и тегами |
| POST | /api/posts | Добавление поста |
| PATCH | /api/posts/:id | Изменение поста |
| DELETE | /api/posts/:id | Удаление поста |

Создание возвращает 201, удаление — 204 без тела, остальные успешные запросы — 200. Неверные данные — 400, отсутствующая запись — 404, конфликт email или удаление автора с постами — 409.

Перед удалением пользователя нужно удалить его посты. PATCH меняет только переданные поля. Если передать tags, список тегов поста заменяется; пустой массив убирает все теги. Сами теги могут остаться в таблице Tag.

## Примеры для Postman

Выбрать Body → raw → JSON. Сначала создать пользователя:

`POST http://localhost:3000/api/users`

```json
{
  "email": "danil@example.com",
  "name": "Данил"
}
```

Затем создать пост. Вместо 1 подставить id созданного пользователя:

`POST http://localhost:3000/api/posts`

```json
{
  "title": "Мой первый пост",
  "content": "Изучаю Node.js",
  "published": true,
  "authorId": 1,
  "tags": ["node", "учеба"]
}
```

Теги добавляются через `connectOrCreate`: существующий тег подключается, новый создается.

Получить список с фильтрами:

```text
GET http://localhost:3000/api/posts?search=ПЕРВЫЙ&published=true&authorId=1&page=1&limit=5
```

Все фильтры можно использовать отдельно или вместе. Поиск идет по части заголовка без учета регистра, в том числе для русского текста. В SQLite Prisma не поддерживает `mode: 'insensitive'`, поэтому здесь заголовки сравниваются через `toLowerCase().includes()`, а найденные id передаются в фильтр Prisma. Для небольшой учебной базы это простой вариант, для большой базы он не подходит.

Ответ списка содержит:

```json
{
  "data": [],
  "meta": { "total": 0, "page": 1, "limit": 5, "pages": 0 }
}
```

По умолчанию page=1, limit=10. Максимальный limit=100. total — число записей после фильтрации, pages — число страниц.

Обновить пост:

```text
PATCH http://localhost:3000/api/posts/1
```

```json
{ "published": false }
```

Удалить пост: `DELETE http://localhost:3000/api/posts/1`.

## Проверка

После миграции:

```powershell
npm test
```

Проверка сама запускает сервер на порту 3093 и выполняет запросы: создание, чтение, изменение, удаление, повторное использование тегов, фильтры, пагинация и ошибки. Она использует текущую учебную базу, создает временного пользователя и два поста, затем удаляет их при успешном прохождении. Созданные теги остаются.

Это локальная учебная работа: регистрации, паролей и проверки прав здесь нет. Поле role хранится в базе, но не ограничивает доступ. Не использовать API для реальных персональных данных и не публиковать как готовый защищенный сервис.

При проверке зависимостей `npm audit` сообщил о 3 high-уязвимостях в цепочке инструмента Prisma 6 (`deepmerge-ts`). Автоматическое исправление предлагает смену основной версии Prisma и ломает настройку этого учебного проекта; оно не применялось.
